Week 3: Linux Bash Scripting & Server Status Report

Automated server monitoring, systemd timers and system diagnostics.

Status: In progress

This project demonstrates automated server monitoring using Linux bash scripting, systemd timers and server status reporting.

Current server status

How the report works

The Bash script collects the server time and time zone, uptime, root filesystem usage, and total and available memory. It writes a new HTML report to a temporary file and then replaces the published report, so the page does not display a partly written file.

The disk status is OK below 80% root filesystem usage and WARNING at 80% or higher. A systemd service runs the script, and its timer starts after boot and schedules another update every minute. This page embeds the latest report from the Flask application.

Commands used

  • date '+%Y-%m-%d %H:%M:%S %Z (%z)' prints the report generation time with its time zone and UTC offset.
  • uptime -p prints how long the server has been running.
  • df -P / | awk 'NR == 2 { print $5 }' uses a pipe to read the root filesystem usage percentage from df.
  • free -h displays memory totals and available memory in human-readable units.

Tests

  • Disk status: 50% produced OK; 80% produced WARNING; 90% produced WARNING.
  • Automatic updates: the enabled systemd timer successfully generated reports in consecutive one-minute intervals. The journal recorded successful runs at 15:10:26, 15:11:26, 15:12:27 and 15:13:28 UTC.
  • Reboot test: after the VM rebooted at 15:15:59 UTC, the Flask application and timer were active. The timer continued updating the report at 15:24:06, 15:25:07 and 15:26:07 UTC, and both public Week 3 URLs returned HTTP 200.

Problem and lesson learned

An initial file transfer failed because the command used app.py without its project folder. Running SCP from the repository root requires the path .\portfolio\app.py and the remote destination; checking the transfer output helped catch the mistake before relying on the server copy.
